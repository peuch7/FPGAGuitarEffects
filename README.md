# digital_effects

A guitar-effects pedal on a Digilent **Zybo Z7-10** (Zynq-7010). The guitar goes into
the board's audio codec. A chain of effects runs in the FPGA fabric, and you edit the
chain from a serial command line.

Everything lives here: the effects, the router that chains them, the board
design, and the ARM software. The effects and the router started out in a
separate simulator repo (VerilogSim), which is now retired; this repo is the
only source.

**To build and run it, see [INSTALL.md](INSTALL.md).**

## How it works

```
                       12.288 MHz MCLK domain (256 clocks per 48 kHz sample)
  SSM2603   ac_recdat  +--------+  sample  +---------------------------------+  sample  +--------+  ac_pbdat  SSM2603
  codec  ------------->| i2s_rx |--------->| router_pl                       |--------->| i2s_tx |----------> codec
  (ADC)                +--------+          |  routing.sv: walks the patch,   |          +--------+            (DAC)
                                           |  one effect after another       |
                                           |  effect_bank.sv: one instance   |
                                           |  of every effect (generated)    |
                                           |  patch_ram.sv: dual-port BRAM --+--- port A, its own clock
                                           +---------------------------------+        |
                                                                                      |
  Zynq PS (ARM) --- M_AXI_GP0 (FCLK0, 50 MHz) --- SmartConnect --- AXI BRAM Controller +   0x4000_0000, 4 KB
      |  UART1: the fx> command line (sw/fx_cli)
      +- I2C0 (EMIO): codec registers
      +- SPI1 + GPIO: front panel, a 480x320 TFT and 5 encoders (docs/front_panel.md)
```

- **Audio never touches the ARM.** Each sample goes through the effects listed in
  the router's patch memory, in order. The whole six-effect chain takes 84 of the
  256 clocks available per sample.
- **The ARM only writes patch memory.** It holds two banks: the CLI writes the one
  the router isn't using, then flips a control word. A patch change never cuts a
  sample in half.
- **Adding an effect doesn't touch the block design.** Effects live inside
  `router_pl`, so a new one changes only generated files. The block design, pins,
  address map and CLI code stay the same.

## Repository layout

| path | what | kind |
|---|---|---|
| `router/rtl/` | router core: `routing.sv`, `patch_ram.sv`, `router_pl.sv`, `effect_contract.svh` | hand-written |
| `effects/<name>/` | one effect: `effect.json` (its spec) and `rtl/` (its sources) | hand-written, registered with `fx.py add` |
| `effects/registry.json` | router id of each effect (append-only), and the power-on preset | written by `fx.py` |
| `presets/<name>.json` | named chains of effects | hand-written |
| `gen/` | effect bank, router header, C tables, Vivado/simulator file lists | **generated** by `fx.py gen`, committed |
| `rtl/` | board RTL: `bclk_div.sv`, `i2s_rx.sv`, `i2s_tx.sv` | hand-written |
| `constraints/zybo_z7_10.xdc` | pins and clock groups | hand-written |
| `vivado/` | `create_project.tcl`, `design_1.tcl` (block design), `build.tcl` | hand-written |
| `vitis/` | `create_workspace.py` (platform + app), `run.tcl` (program over JTAG) | hand-written |
| `sw/fx_cli/` | the bare-metal app: codec setup, patch editing, the command line and the front panel | hand-written, effect-agnostic |
| `scripts/fx.py`, `scripts/fxlib/` | the effect manager and code generator, and its tests | hand-written |
| `sim/` | testbenches and checks that run without a board (see below) | hand-written |
| `build/` | Vivado project, Vitis workspace, simulation output | tool output, ignored |

**Never edit `gen/` by hand.** It is regenerated from `effects/`, `presets/` and the
registry by `fx.py gen`, and `fx.py check` fails if it is stale. Everything else is
ordinary source: edit it in place.

`effects/chorus/rtl/chorus_sine_table.svh` is also generated, by
`effects/chorus/gen_sine_table.py`. Rerun that script if you change chorus's
`base_ms` or `depth` knobs.

## Adding or updating an effect

```sh
python3 scripts/fx.py add path/to/tremolo.json            # any RTL, described by a spec
python3 scripts/fx.py add path/to/tremolo.sv              # just the RTL: a starting spec is derived from its ports
python3 scripts/fx.py add effects/delay/effect.json       # after editing an effect: re-register it (same id)
python3 scripts/fx.py check                               # validate, lint, simulate each effect in the router
```

Each `add` regenerates `gen/`. After that, rebuild: re-run the scripts or click
through the GUI, as INSTALL.md describes. The full guide, including the spec format,
is [docs/adding_an_effect.md](docs/adding_an_effect.md).

## The command line

Connect a serial terminal to the board's USB-UART at 115200 8N1.

```
fx> preset pedalboard          load a preset
fx> add chorus rate=1.2        append an effect; knobs not given take their defaults
fx> set delay mix=40%          0.4 / 40% are natural units, 26214 is the raw 16-bit value
fx> mv chorus 1                reorder
fx> rm 2                       remove by position or name
fx> fx delay                   knobs, ranges, units, defaults
fx> bypass delay               out of the signal path, knobs kept; again to put it back
fx> show / status              the chain, router flags, whether audio is flowing
fx> gain 6 / vol -10           codec line-in gain, headphone volume (dB)
```

The front panel does the same with a screen and five knobs, and the two stay in sync:
see [docs/front_panel.md](docs/front_panel.md).

The board LEDs show the router's state:
- LD0: overrun (the patch is too slow).
- LD1: an effect timed out.
- LD2: glows while audio is being processed.
- LD3: the audio domain is out of reset.

## Checks that run without a board

```sh
make -C sim            # everything below
make -C sim check      # specs, gen/ freshness, Verilator lint, each effect through the router, cycle budget
make -C sim audio      # pin to pin: codec model -> i2s_rx -> router -> i2s_tx -> codec model
make -C sim delay      # regression: shortening the delay while it runs
make -C sim cli        # the CLI firmware on the host against a fake patch memory
make -C sim ui         # the front panel on the host: scripted knobs, screenshots
make -C sim gen-tests  # unit tests of fx.py, including adding effects end to end (needs pytest)
```

These need Verilator 5, a C compiler and Python 3. Vivado and Vitis are only needed
to build for the board.

## Known issues and limits

- **echo** is a passthrough stub (`effects/echo/rtl/echo.sv`). It routes correctly but
  does nothing yet.
- **Overdrive:** `tone` and `asymmetry` are accepted but not implemented in the RTL
  yet. `drive` is a gain: `drive=8.0` is 8x. A plain integer is always the raw field
  (Q8.8, so `drive=8` is 1/32x).
- **Leftover audio:** an effect's state freezes while it is out of the chain. A delay
  removed and added back later first plays what was in its buffer then. Set its
  `mix` to 0 for a moment, or wait out the delay.
- **Sticky flags:** overrun and timeout stay latched until the next FPGA reset.
- **Block RAM budget:** the 1 s delay line takes most of the Z7-10's 60 RAMB36. The
  six effects are estimated at about 50, so a second long delay line won't fit.
  `fx.py check` can't measure BRAM; `vivado/build.tcl` prints the real figure.
- **Cycle budget:** the router must finish each sample within 256 MCLK clocks.
  `fx.py check` measures every effect and checks the worst 7-stage chain against that.
- **Input channel:** the codec's **right** channel is the input (`rtl/i2s_rx.sv`). A
  mono guitar cable plugged straight into the stereo LINE IN jack grounds that
  channel. Use a mono-to-dual-mono adapter.
- **One instance per effect:** a chain can't hold the same effect twice, and holds at
  most 7 stages.
- **No audio-level tests yet.** VerilogSim's reference models and WAV harness didn't
  come along. The checks here prove effects route, answer in time, and that the
  router, I2S and CLI are correct, but not how an effect sounds.
  `sim/tb_router.sv` can run a recording through any patch (`+in`, `+out`).
